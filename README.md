# OneCanRunIsOK

5人小组于6周时间内基于Unity游戏引擎开发了一款单机FPS游戏。

游戏包括：
一、游戏类型定位
游戏类型定位为有加点系统的fps+roguelike游戏

二、游戏玩法定位
	单人、第一人称射击、PVE、升级、敌人Buff随机生成

 
三、美术风格定位
  简约动画风
  
四、系统模块


	1. 武器系统
设计了近战、子弹类、充能类、激光类四种武器。近战是使用设定前方包围盒，判定是否有敌人在包围盒中，并且在动画的帧事件中进行伤害结算；子弹类和充能类都是射击出一个抛掷物（子弹和能量球），碰撞时进行伤害结算，不同的是一个是需要换弹，另一个是自动充能的；激光类则是从主视角中心进行射线检测，让后让枪口和第一个检测的物体进行连线射出激光。

 	2. 子弹系统
		子弹是除了近战武器外其他三种武器都使用到的系统。武器开火时让子弹射出，但是由于枪口设置是出于屏幕的左下角（腰射），如果不加处理，并不会打到屏幕中央指向的方向，且距离越近，效果越差，因此除了激光类较为特殊，前文以及介绍过了，其他两类都是需要进行弹道修正，通过每帧将子弹往屏幕中偏移一点，在设定的帧数后，子弹就会表现的是从屏幕中央射出的效果。
  
	2. 缓存池系统
		为怪物、子弹、伤害飘字和伤害来源设计了缓存池。为了不在游戏过程中卡顿，在游戏正式开始前就为这几个物体创建了一定数量对应物体。当其他系统需要使用到它们时，不需要重新重建，将从池子中获得对应实体，并对它们进行操作。不需要时，就释放它们，即重新将它们不可见，不再更新，放回缓存池中，标为可用，并不销毁它们。优化了游戏性能。
  
	3. 阵营系统
		整体分为三个阵营：友方、敌人和中立。其他系统根据需要对阵营进行必要的判断，如怪物攻击时判断获得的碰撞体的阵营是敌人时，不会对他们伤害计算，而是友方时会进行伤害计算。
  
	4. 属性系统
		基础属性包括血量、技巧、耐力、智力、力量、等级。而具体属性包括物理/魔法攻击力、物理/魔法防御、移速、恢复速度等。等级提升或者获得Buff时，会对不同属性有一定的加成或削弱。怪物和玩家都拥有此系统。
  
	5. Buff系统
		Buff系统中不仅有Buff还有DeBuff。Buff功能上分为两类增益类和特殊类，增益类Buff会对属性有增益或者削弱，特殊类有比如死亡一次可以复活的功能。Buff事件上分为两类，有时效的、无限时间的，无限时间类可以叠层。
  
	6. 技能系统
		技能分为三大类：伤害类、增益Buff类和召唤类。伤害类调用子弹系统的接口，将这类技能伤害定义为特殊的子弹。Buff类调用了Buff系统，使用技能获得临时的属性加成。召唤类调用了AI系统，为与怪物相对的友方阵营角色AI。
  
	7. AI系统
		AI系统包括自动寻路、决策树和攻击物检测。自动寻路和攻击物检测主要是普通敌人和召唤物在使用，是较为简单的FSM。未检测到非己方阵营时，会进行巡检；如果检测到了，怪物的状态机就会发生变化，会进行攻击、追击。Boss的行为更加复杂还有决策树对行为进行管理。
  
	8. 敌人系统
		敌人系统沿用了AI系统、属性系统、武器系统等多个系统的接口。还有设定敌人的刷新机制——随机刷新中某种怪物所占权重，最大数量，刷新时间等等。
  
	9. 交互系统
		包括Boss机关的触发、打开宝箱、拾取武器等功能。
  
	10. 玩家系统
		玩家对于武器系统、交互系统、技能系统等等的输入控制。
  
	11. UI系统
		包括了背包状态栏，小地图，伤害来源，伤害飘字，低血量，武器栏状态时的反馈等等UI。其中伤害来源和伤害飘字涉及到了多个不同坐标系的转换，伤害来源的大小变化也运用到了反比例函数。
